# Week20 - My AI System

> [!abstract] 이번 주의 설계 질문
> 앞선 기술 세 가지를 하나의 의도로 조합하고 내가 원하는 성질을 증명한다.

> [!tip] 진행 방법
> **Build → Measure → Tune → Break → Rebuild.** 먼저 baseline 하나, 변수 하나의 비교 실험, break test 하나를 끝낸 뒤 나머지를 확장한다. 아래 수치와 실습 규모는 학습용 제안이며 제품의 기본값이나 최적값이 아니다.
> 제품 관찰과 직접 만드는 축소 구현을 구분한다. 공개되지 않은 내부 구조는 관찰·가설로 표시하고, 실제 사용한 제품·모델·라이브러리 버전을 기록한다.

**학습용 흐름:** 사용자 요구 → 입력·상태 → 핵심 처리 → 근거·행동 → 검증 → 출력·피드백

## 1. 핵심 원리 이해

- [ ] 내가 해결할 문제와 원하는 성질을 각각 한 문장으로 적는다. 예: ‘근거는 분명하고 기억은 절제된 개인 학습 도우미’.
- [ ] 앞선 기술 세 가지를 고르고 각각이 필요한 이유와 빠졌을 때 생기는 손실을 설명한다.

## 2. 시스템 아키텍처 관찰

- [ ] 입력부터 결과까지 하나의 흐름을 그리고 각 모듈의 입력·출력·실패 상태를 정한다.
- [ ] 검색·기억·도구 같은 모듈 간 데이터가 중복되거나 책임이 겹치는 지점을 찾는다.

## 3. 조정 가능한 변수 (Knobs)

- [ ] 내 핵심 가치와 연결되는 변수 세 개만 고른다. 예: 검색 top-k, 기억 저장 임계값, 최대 조사 라운드.
- [ ] 각 변수의 기대 효과·부작용·허용 범위를 먼저 적고 모델 또는 버전을 고정한다.

## 4. Baseline 구현

- [ ] 가장 흔한 사용자 시나리오 하나가 끝까지 동작하는 최소 구현을 만든다.
- [ ] 같은 시나리오를 해결하는 더 단순한 대조군과 평가 사례 10개를 준비한다.

## 5. 한 변수씩 바꾸는 실험

- [ ] 선택한 변수 중 하나만 바꾸어 가설을 시험한 뒤 나머지 변수는 별도 실험으로 진행한다.
- [ ] 모듈을 하나씩 제거하는 ablation으로 세 기술이 각각 실제로 기여하는지 확인한다.

## 6. 성능 측정 지표

- [ ] 문제 해결률을 주 지표로 정하고 내 핵심 가치에 맞는 보조 지표 하나를 고른다.
- [ ] 지연·비용·개입 횟수 중 제약을 적고, 튜닝에 쓰지 않은 별도 사례로 최종 결과를 확인한다.

## 7. 의도적으로 망가뜨리는 Break Test

- [ ] 근거 없음·상충 기억·도구 실패 중 내 시스템에 해당하는 실패 시나리오를 실행한다.
- [ ] 입력부터 최종 출력까지 오류가 어떻게 전파되는지 확인하고, 틀린 성공 보고나 무한 반복을 찾는다.

## 8. 내 방식으로 재설계

- [ ] 실험에서 기여하지 못한 요소를 단순화하고, 내 핵심 가치를 가장 크게 바꾸는 규칙 하나를 다시 설계한다.
- [ ] 기존 baseline·수정안·최종안의 결과를 비교하고 보류·복구·종료 동작을 확인한다.

## 9. 최종 회고

- [ ] ‘나는 무엇을 바꿨고, 어떤 성질이 왜 달라졌는가’를 결과와 함께 설명한다.
- [ ] 20주에서 가장 아름다웠던 설계 세 가지, 버릴 습관 하나, 다음에 깊게 팔 주제 하나를 적는다.
