# Week14 - Knowledge Graph + LLM

> [!abstract] 이번 주의 설계 질문
> LLM의 언어 이해와 그래프의 명시적 관계를 결합해 근거 경로를 설명한다.

> [!tip] 진행 방법
> **Build → Measure → Tune → Break → Rebuild.** 먼저 baseline 하나, 변수 하나의 비교 실험, break test 하나를 끝낸 뒤 나머지를 확장한다. 아래 수치와 실습 규모는 학습용 제안이며 제품의 기본값이나 최적값이 아니다.
> 제품 관찰과 직접 만드는 축소 구현을 구분한다. 공개되지 않은 내부 구조는 관찰·가설로 표시하고, 실제 사용한 제품·모델·라이브러리 버전을 기록한다.

**학습용 흐름:** 문서·질문 → 엔터티 연결 → 그래프 질의 → 경로·출처 회수 → LLM 답변

## 1. 핵심 원리 이해

- [ ] 트리플(subject, predicate, object)과 자연어 문장이 표현하는 정보의 차이를 설명한다.
- [ ] Week03의 커뮤니티 요약과 달리 이번 주는 스키마·엔터티 식별·근거 경로에 집중한다.

## 2. 시스템 아키텍처 관찰

- [ ] 별칭 → 고유 ID → 관계 질의 → 원문 근거의 연결을 그린다.
- [ ] LLM이 관계를 추출하는 단계와 그래프를 조회해 답변하는 단계를 분리한다.

## 3. 조정 가능한 변수 (Knobs)

- [ ] 엔터티 병합 기준, 관계 어휘, 탐색 hop, 엣지 확신도 필터를 후보로 둔다.
- [ ] 랭킹 점수를 결합한다면 각 항의 범위와 방향을 맞추고 graph distance는 가까울수록 높은 점수가 되게 변환한다.

## 4. Baseline 구현

- [ ] 프로젝트·기술·문제·해결책으로 20~30개의 수동 검증 트리플을 만든다.
- [ ] 1~2 hop 질문 10개에 그래프 경로와 원문을 보여주는 답변기를 만든다.

## 5. 한 변수씩 바꾸는 실험

- [ ] 같은 그래프에서 최대 hop만 1/2/3으로 바꾼다.
- [ ] 별도 실험으로 별칭 병합 규칙 하나만 바꾸고 잘못 합쳐진 노드와 찾지 못한 노드를 비교한다.

## 6. 성능 측정 지표

- [ ] 엔터티 연결 정확도, 정답 경로 회수율, 근거로 지지된 답변 비율을 기록한다.
- [ ] 질의당 방문 노드 수·지연과 사람이 경로를 확인하는 시간을 측정한다.

## 7. 의도적으로 망가뜨리는 Break Test

- [ ] 동명이인, 반대 방향의 관계, 서로 모순되는 사실을 넣는다.
- [ ] 그래프에 없는 관계를 질문했을 때 LLM이 경로를 지어내는지 확인한다.

## 8. 내 방식으로 재설계

- [ ] uses 같은 일반 관계 대신 solved·depends_on·contradicts 중 필요한 관계만 추가한다.
- [ ] 모든 답변에 근거 경로와 미확인 연결을 구분해 표시하고 이전 출력과 비교한다.

## 9. 최종 회고

- [ ] 구조화가 도움이 된 질문과 자연어 검색만으로 충분했던 질문을 적는다.
- [ ] 내가 고른 관계 어휘가 사고방식을 어떻게 바꿨는지 정리한다.

## 실험 기록

> [!note] 비교 원칙
> 입력·평가 사례·모델·예산을 고정하고 변수 하나만 바꾼다. 확률적인 결과는 가능하면 조건별 3회 이상 반복해 평균 또는 중앙값과 범위를 함께 적는다. 개선안 선택에 쓴 사례와 최종 확인 사례를 구분한다. Break test는 복사본·합성 자료·모의 환경에서 수행한다.
