# Week11 - AlphaGo

> [!abstract] 이번 주의 설계 질문
> 학습된 직관과 탐색에 쓰는 계산량이 의사결정에 기여하는 방식을 구분한다.

> [!tip] 진행 방법
> **Build → Measure → Tune → Break → Rebuild.** 먼저 baseline 하나, 변수 하나의 비교 실험, break test 하나를 끝낸 뒤 나머지를 확장한다. 아래 수치와 실습 규모는 학습용 제안이며 제품의 기본값이나 최적값이 아니다.
> 제품 관찰과 직접 만드는 축소 구현을 구분한다. 공개되지 않은 내부 구조는 관찰·가설로 표시하고, 실제 사용한 제품·모델·라이브러리 버전을 기록한다.

**학습용 흐름:** 보드 상태 → 정책·가치 평가 → MCTS 탐색 → 행동 선택 → 환경 변화 → 학습 자료

## 1. 핵심 원리 이해

- [ ] 정책(policy)은 유망한 행동을, 가치(value)는 상태의 전망을 추정한다는 차이를 설명한다.
- [ ] 2016 AlphaGo의 지도학습·강화학습·탐색과 AlphaGo Zero/AlphaZero의 학습 구성을 섞지 않는다.

## 2. 시스템 아키텍처 관찰

- [ ] 선택 → 확장 → 평가 → 역전파의 Monte Carlo Tree Search 흐름을 따라간다.
- [ ] 탐색 시뮬레이션 횟수를 늘리는 것과 모델을 다시 학습시키는 것을 별도 과정으로 그린다.

## 3. 조정 가능한 변수 (Knobs)

- [ ] 시뮬레이션 수 10/100/500, 탐색 상수, 선택 온도를 후보로 정한다.
- [ ] 정책 prior나 가치 평가기를 넣는 경우 기존 탐색 규칙과 결합되는 위치를 기록한다.

## 4. Baseline 구현

- [ ] 틱택토 또는 작은 보드 게임에서 무작위 정책과 MCTS를 구현한다.
- [ ] 학습 모델 없이 시작한 모형임을 명시하고, 완전 탐색 정답이 가능한 상태로 의사결정을 검증한다.

## 5. 한 변수씩 바꾸는 실험

- [ ] 같은 초기 상태와 상대 정책에서 시뮬레이션 수만 바꾼다.
- [ ] 여러 seed와 선공·후공을 균형 있게 배치해 승률 변화를 비교한다.

## 6. 성능 측정 지표

- [ ] 승/무/패 비율, 수당 시간, 방문 노드 수를 기록한다.
- [ ] 정답 행동이 알려진 상태에서 최선 행동 선택률을 측정해 승률만으로 놓치는 오류를 본다.

## 7. 의도적으로 망가뜨리는 Break Test

- [ ] 한 수 뒤 함정이 있는 상태와 반드시 막아야 하는 상태를 준비한다.
- [ ] 평가기를 일부러 편향시키고 탐색 예산이 적을 때 잘못된 직관을 극복하는지 확인한다.

## 8. 내 방식으로 재설계

- [ ] 강한 플레이보다 빠른 반응이나 다양한 플레이 중 내가 원하는 성질을 정한다.
- [ ] 선택 온도 또는 탐색 예산 하나를 조정해 성능 손실과 행동 변화의 관계를 보여준다.

## 9. 최종 회고

- [ ] 탐색이 직관을 교정한 사례와 계산을 더 써도 나아지지 않은 사례를 적는다.
- [ ] 작은 모형에서 배운 원리와 실제 AlphaGo를 재현하지 않은 부분을 구분한다.

## 실험 기록

> [!note] 비교 원칙
> 입력·평가 사례·모델·예산을 고정하고 변수 하나만 바꾼다. 확률적인 결과는 가능하면 조건별 3회 이상 반복해 평균 또는 중앙값과 범위를 함께 적는다. 개선안 선택에 쓴 사례와 최종 확인 사례를 구분한다. Break test는 복사본·합성 자료·모의 환경에서 수행한다.
