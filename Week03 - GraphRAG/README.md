# Week03 - GraphRAG

> [!abstract] 이번 주의 설계 질문
> 관계와 커뮤니티 요약이 어떤 질문에서 단순 문서 검색보다 유리한지 검증한다.

> [!tip] 진행 방법
> **Build → Measure → Tune → Break → Rebuild.** 먼저 baseline 하나, 변수 하나의 비교 실험, break test 하나를 끝낸 뒤 나머지를 확장한다. 아래 수치와 실습 규모는 학습용 제안이며 제품의 기본값이나 최적값이 아니다.
> 제품 관찰과 직접 만드는 축소 구현을 구분한다. 공개되지 않은 내부 구조는 관찰·가설로 표시하고, 실제 사용한 제품·모델·라이브러리 버전을 기록한다.

**학습용 흐름:** 문서 → 엔터티·관계 추출 → 그래프 → 커뮤니티·요약 → local/global 검색 → 근거 답변

## 1. 핵심 원리 이해

- [ ] 엔터티 주변을 찾는 local search와 전체 주제를 묻는 global search의 차이를 설명한다.
- [ ] 그래프 추출 오류와 커뮤니티 요약의 정보 손실이 답변에 전파되는 경로를 찾는다.

## 2. 시스템 아키텍처 관찰

- [ ] 문서 문장 → 노드·엣지 → 커뮤니티 요약 → 최종 답변의 출처를 역추적한다.
- [ ] 단순 다중 홉 그래프 검색과 Microsoft GraphRAG의 커뮤니티 기반 접근을 구분한다.

## 3. 조정 가능한 변수 (Knobs)

- [ ] 엔터티 유형, 관계 유형, 커뮤니티 세분화 정도, 요약 길이를 조정 후보로 적는다.
- [ ] 자체 그래프 검색의 hop 1/2/3과 검색 예산을 구분하고, 이를 모든 GraphRAG 모드의 공통 옵션으로 가정하지 않는다.

## 4. Baseline 구현

- [ ] 문서 10개로 일반 RAG 대조군을 먼저 만들고 동일 자료의 작은 그래프를 만든다.
- [ ] 국소 질문 5개와 전체 주제 질문 5개를 준비해, 작은 커뮤니티 요약을 이용한 답변 경로를 추가한다.

## 5. 한 변수씩 바꾸는 실험

- [ ] 같은 추출 결과에서 커뮤니티 요약 사용 여부만 바꿔 전체 주제 질문을 비교한다.
- [ ] 별도 실험으로 엔터티 유형에 Problem/Decision을 추가하고 기존 질문의 근거 회수 변화를 확인한다.

## 6. 성능 측정 지표

- [ ] 수동 정답표로 엔터티·관계 precision/recall과 질문별 근거 회수율을 계산한다.
- [ ] 국소·전체 질문의 답변 품질을 따로 기록하고 색인 비용과 질의 비용을 분리한다.

## 7. 의도적으로 망가뜨리는 Break Test

- [ ] 동명이인 노드를 잘못 합치거나 허브 노드에 무관한 관계를 추가한 복사본을 시험한다.
- [ ] 출처 없는 관계를 넣어, 잘못된 연결이 그럴듯한 설명으로 바뀌는지 확인한다.

## 8. 내 방식으로 재설계

- [ ] 내 노트에 맞게 Problem → Decision → Evidence 같은 관계 어휘를 정한다.
- [ ] 관계마다 원문·확신도·시점을 남기고, 출처가 약한 연결을 제외하는 검색을 비교한다.

## 9. 최종 회고

- [ ] 그래프가 실제로 도움이 된 질문과 일반 RAG면 충분했던 질문을 적는다.
- [ ] 지식 구조에서 아름답다고 느낀 연결 하나와 그 연결을 과신하면 생길 오류를 기록한다.

## 실험 기록

> [!note] 비교 원칙
> 입력·평가 사례·모델·예산을 고정하고 변수 하나만 바꾼다. 확률적인 결과는 가능하면 조건별 3회 이상 반복해 평균 또는 중앙값과 범위를 함께 적는다. 개선안 선택에 쓴 사례와 최종 확인 사례를 구분한다. Break test는 복사본·합성 자료·모의 환경에서 수행한다.
