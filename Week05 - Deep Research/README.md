# Week05 - Deep Research

> [!abstract] 이번 주의 설계 질문
> 조사를 오래 하는 것과 불확실성을 실제로 줄이는 것을 구분한다.

> [!tip] 진행 방법
> **Build → Measure → Tune → Break → Rebuild.** 먼저 baseline 하나, 변수 하나의 비교 실험, break test 하나를 끝낸 뒤 나머지를 확장한다. 아래 수치와 실습 규모는 학습용 제안이며 제품의 기본값이나 최적값이 아니다.
> 제품 관찰과 직접 만드는 축소 구현을 구분한다. 공개되지 않은 내부 구조는 관찰·가설로 표시하고, 실제 사용한 제품·모델·라이브러리 버전을 기록한다.

**학습용 흐름:** 질문 → 조사 계획 → 하위 질문 → 검색·원문 읽기 → 증거표 → 공백 점검 → 보고서

## 1. 핵심 원리 이해

- [ ] 일회성 검색 답변과 조사 중 발견한 공백을 다시 찾는 반복 조사의 차이를 설명한다.
- [ ] 특정 제품의 비공개 구현을 추정하지 않고, 자신의 조사 절차를 설계 대상으로 삼는다.

## 2. 시스템 아키텍처 관찰

- [ ] 하위 질문마다 근거·반대 근거·미해결 항목을 보관하는 상태를 그린다.
- [ ] 검색 실패, 원문 접근 실패, 상충하는 근거가 다음 조사 단계에 어떻게 반영되는지 관찰한다.

## 3. 조정 가능한 변수 (Knobs)

- [ ] 자체 조사 루프의 하위 질문 수, 최대 검색 횟수, 원문 수, 중단 조건을 조정한다.
- [ ] 출처 다양성 기준과 ‘새 근거가 더 이상 나오지 않음’의 판정 기준을 정한다.

## 4. Baseline 구현

- [ ] 범위가 좁은 기술 질문 하나를 정해 하위 질문 3개, 출처 5개 이내의 조사기를 만든다.
- [ ] 같은 질문의 일회성 검색 답변을 대조군으로 저장하고 주장·출처·날짜가 있는 증거표를 만든다.

## 5. 한 변수씩 바꾸는 실험

- [ ] 동일한 저장 자료와 모델로 조사 라운드만 1/2/3회로 바꾼다.
- [ ] 추가 라운드에서 새로 해결된 하위 질문과 반복된 검색을 따로 센다.

## 6. 성능 측정 지표

- [ ] 질문 충족률 = 근거 있게 답한 하위 질문 수 / 사전 정의한 하위 질문 수를 계산한다.
- [ ] 근거 없는 주장 수, 독립 출처 수, 추가 호출당 새 근거 수, 시간·비용을 기록한다.

## 7. 의도적으로 망가뜨리는 Break Test

- [ ] 서로 인용만 하는 글들과 상반된 결론을 넣어 순환 인용을 발견하는지 확인한다.
- [ ] 검색 결과가 거의 없는 질문에서 억지 보고서 대신 미확인 항목과 종료 이유를 남기는지 본다.

## 8. 내 방식으로 재설계

- [ ] ‘완결된 척하는 보고서’보다 ‘확인한 것과 남은 질문이 보이는 보고서’라는 원칙을 적용한다.
- [ ] 새 근거가 없는 라운드에서 멈추는 규칙을 넣고 품질 손실과 절약한 비용을 비교한다.

## 9. 최종 회고

- [ ] 어떤 추가 검색이 판단을 실제로 바꿨는지 한 사례를 적는다.
- [ ] 만족스러운 조사 종료 조건과 다음번에 사람이 먼저 판단해야 할 질문을 정리한다.

## 실험 기록

> [!note] 비교 원칙
> 입력·평가 사례·모델·예산을 고정하고 변수 하나만 바꾼다. 확률적인 결과는 가능하면 조건별 3회 이상 반복해 평균 또는 중앙값과 범위를 함께 적는다. 개선안 선택에 쓴 사례와 최종 확인 사례를 구분한다. Break test는 복사본·합성 자료·모의 환경에서 수행한다.
