# Week12 - AlphaFold

> [!abstract] 이번 주의 설계 질문
> 예측 구조를 정답처럼 보는 대신 근거·신뢰도·해석 한계를 함께 읽는다.

> [!tip] 진행 방법
> **Build → Measure → Tune → Break → Rebuild.** 먼저 baseline 하나, 변수 하나의 비교 실험, break test 하나를 끝낸 뒤 나머지를 확장한다. 아래 수치와 실습 규모는 학습용 제안이며 제품의 기본값이나 최적값이 아니다.
> 제품 관찰과 직접 만드는 축소 구현을 구분한다. 공개되지 않은 내부 구조는 관찰·가설로 표시하고, 실제 사용한 제품·모델·라이브러리 버전을 기록한다.

**학습용 흐름:** 서열·진화 정보 → 표현 갱신 → 구조 예측 → 반복 보정 → 신뢰도 평가

## 1. 핵심 원리 이해

- [ ] 이번 주는 AlphaFold 2를 기준으로 MSA, 잔기 쌍 표현, 구조 예측의 역할을 설명한다.
- [ ] pLDDT의 국소 신뢰도와 PAE의 잔기 간 상대 배치 불확실성을 구분하고 물리적 안정성과 동일시하지 않는다.

## 2. 시스템 아키텍처 관찰

- [ ] 서열·MSA·template 정보가 표현과 구조 모듈로 흐르는 경로를 관찰한다.
- [ ] recycling이 이전 예측을 다시 반영하는 과정임을 설명하고 다른 세대의 구조를 섞지 않는다.

## 3. 조정 가능한 변수 (Knobs)

- [ ] 실행 환경이 지원한다면 MSA 깊이, template 사용, recycle 수를 후보로 정한다.
- [ ] 실행 자원이 없으면 공개 구조의 신뢰도 필터 기준을 조정하며, 이를 모델 자체 최적화와 구분한다.

## 4. Baseline 구현

- [ ] 공개 예측 구조 하나를 골라 잔기별 pLDDT를 읽고 낮은 신뢰도 구간을 표시하는 작은 분석을 만든다.
- [ ] 가능한 경우 동일 서열·동일 잔기 범위의 실험 구조와 비교하고, 대형 모델 재학습은 baseline 범위에 넣지 않는다.

## 5. 한 변수씩 바꾸는 실험

- [ ] 기본 실험은 같은 구조에서 pLDDT 표시 임계값만 50/70/90으로 바꿔 남는 구간을 비교한다.
- [ ] 실행 가능한 환경이 있을 때만 recycle 수 하나를 바꾸고 입력 자료와 다른 설정을 고정한다.

## 6. 성능 측정 지표

- [ ] 임계값 이상 잔기 비율과 낮은 신뢰도 구간의 위치를 기록한다.
- [ ] 정답 구조가 있으면 정렬·잔기 대응·결측 구간을 맞춘 뒤 RMSD 또는 lDDT를 사용하고, 없으면 정확도를 측정했다고 하지 않는다.

## 7. 의도적으로 망가뜨리는 Break Test

- [ ] 낮은 신뢰도 루프나 도메인 사이 높은 PAE 구간을 골라 전체 구조가 확정된 것처럼 해석하는 오류를 찾는다.
- [ ] 잔기 번호가 어긋나거나 일부가 누락된 비교 자료를 넣어 분석이 불일치를 잡아내는지 확인한다.

## 8. 내 방식으로 재설계

- [ ] 예쁜 3D 그림보다 ‘어디를 믿고 어디를 보류할지’가 보이는 보고 형태로 바꾼다.
- [ ] 구조 그림에 신뢰도와 비교 가능한 잔기 범위를 표시해 과도한 해석을 줄인다.

## 9. 최종 회고

- [ ] 높은 국소 신뢰도와 확실한 기능 설명이 왜 다른지 자신의 말로 적는다.
- [ ] 내가 조정한 것이 예측 과정인지 해석·표시 과정인지, 남은 검증은 무엇인지 정리한다.

## 실험 기록

> [!note] 비교 원칙
> 입력·평가 사례·모델·예산을 고정하고 변수 하나만 바꾼다. 확률적인 결과는 가능하면 조건별 3회 이상 반복해 평균 또는 중앙값과 범위를 함께 적는다. 개선안 선택에 쓴 사례와 최종 확인 사례를 구분한다. Break test는 복사본·합성 자료·모의 환경에서 수행한다.
