# Week18 - Genie & World Models

> [!abstract] 이번 주의 설계 질문
> 행동에 따른 상태 예측과 보기 좋은 영상 생성을 구분하고 예측 오차의 누적을 본다.

> [!tip] 진행 방법
> **Build → Measure → Tune → Break → Rebuild.** 먼저 baseline 하나, 변수 하나의 비교 실험, break test 하나를 끝낸 뒤 나머지를 확장한다. 아래 수치와 실습 규모는 학습용 제안이며 제품의 기본값이나 최적값이 아니다.
> 제품 관찰과 직접 만드는 축소 구현을 구분한다. 공개되지 않은 내부 구조는 관찰·가설로 표시하고, 실제 사용한 제품·모델·라이브러리 버전을 기록한다.

**학습용 흐름:** 관측·행동 이력 → 상태 표현 → 다음 상태 예측 → rollout → 실제 환경과 비교

## 1. 핵심 원리 이해

- [ ] 상태 전이 모델과 픽셀 생성 모델이 각각 무엇을 예측하는지 설명한다.
- [ ] 원래 Genie의 비디오 기반 latent action 학습과, 이번 실습의 명시적 행동 라벨 모델을 구분한다.

## 2. 시스템 아키텍처 관찰

- [ ] 관측 인코딩·행동 표현·시간적 예측·출력 복원 단계를 그린다.
- [ ] 실제 환경 상태를 쓰는 teacher forcing과 자기 예측을 다시 넣는 rollout의 차이를 관찰한다.

## 3. 조정 가능한 변수 (Knobs)

- [ ] 이력 길이, 상태 표현의 세밀함, rollout 길이, 학습 데이터의 행동 다양성을 후보로 정한다.
- [ ] 모델 크기나 학습률을 조정하기 전에 상태에 필요한 정보가 빠지지 않았는지 확인한다.

## 4. Baseline 구현

- [ ] 작은 격자 환경의 (상태, 행동, 다음 상태) 전이를 모은다.
- [ ] 관측 빈도로 다음 상태를 예측하는 표 기반 모델을 만들고 규칙 기반 환경을 정답으로 사용한다.

## 5. 한 변수씩 바꾸는 실험

- [ ] 같은 모델에서 rollout 길이만 1/5/10으로 바꿔 오차 누적을 관찰한다.
- [ ] 별도 실험으로 학습 데이터에서 특정 행동 비율만 줄여 데이터 coverage의 영향을 확인한다.

## 6. 성능 측정 지표

- [ ] 1-step 상태 일치율과 H-step 전체 경로 일치율을 나눠 기록한다.
- [ ] 벽 통과 같은 불가능한 전이 수, 미관측 상태·행동 비율, 예측 시간도 기록한다.

## 7. 의도적으로 망가뜨리는 Break Test

- [ ] 학습 때 없던 배치·가려진 상태·빠진 행동을 입력한다.
- [ ] 작은 초기 예측 오류를 넣고 긴 rollout에서 현실과 얼마나 빨리 멀어지는지 확인한다.

## 8. 내 방식으로 재설계

- [ ] 시각적 세부보다 내가 중요하게 보는 충돌·위치·목표 도달 정보를 상태에 남긴다.
- [ ] 불확실하거나 처음 보는 상태에서는 예측을 보류하거나 실제 관측으로 갱신하도록 바꾼다.

## 9. 최종 회고

- [ ] 보기 좋은 예측과 행동 결정에 유용한 예측의 차이를 적는다.
- [ ] 표현·데이터·누적 오차 중 가장 큰 한계와 Genie를 재현하지 않은 범위를 정리한다.

## 실험 기록
