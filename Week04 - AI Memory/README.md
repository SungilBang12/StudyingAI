# Week04 - AI Memory

> [!abstract] 이번 주의 설계 질문
> 많이 저장하는 기억보다 적절하게 저장·수정·잊는 기억을 설계한다.

> [!tip] 진행 방법
> **Build → Measure → Tune → Break → Rebuild.** 먼저 baseline 하나, 변수 하나의 비교 실험, break test 하나를 끝낸 뒤 나머지를 확장한다. 아래 수치와 실습 규모는 학습용 제안이며 제품의 기본값이나 최적값이 아니다.
> 제품 관찰과 직접 만드는 축소 구현을 구분한다. 공개되지 않은 내부 구조는 관찰·가설로 표시하고, 실제 사용한 제품·모델·라이브러리 버전을 기록한다.

**학습용 흐름:** 대화 → 기억 후보 추출 → 저장 판단 → 병합·수정 → 검색 → 답변 반영 → 삭제

## 1. 핵심 원리 이해

- [ ] 작업 문맥, 사건 기억, 사용자 선호를 구분하고 각각의 유효 기간을 설명한다.
- [ ] 사용자가 직접 말한 사실과 모델이 추론한 성향을 별도 정보로 다룬다.

## 2. 시스템 아키텍처 관찰

- [ ] 기억의 원문·사용자 ID·생성 시점·수정 이력을 추적한다.
- [ ] 추출, 저장, 검색, 답변 사용 중 어느 단계에서 오류가 생겼는지 분리한다.

## 3. 조정 가능한 변수 (Knobs)

- [ ] 자체 구현의 저장 임계값, 검색 top-k, 시간 감쇠, 중복 병합 기준을 정한다.
- [ ] 오래된 선호와 새 선호가 충돌할 때 덮어쓰기·이력 보존·재확인 중 적용 규칙을 정한다.

## 4. Baseline 구현

- [ ] 가상 사용자 두 명과 선호 변경이 포함된 합성 대화 20개를 만든다.
- [ ] 작은 JSON 또는 SQLite 저장소로 저장·검색·수정·삭제를 구현하고 기억 없는 답변과 비교한다.

## 5. 한 변수씩 바꾸는 실험

- [ ] 검색 조건을 고정한 채 저장 임계값만 낮음/중간/높음으로 바꾼다.
- [ ] 별도 실험에서 최근성 가중치 하나만 바꾸고 변경 전 선호가 다시 등장하는지 본다.

## 6. 성능 측정 지표

- [ ] 저장 precision = 저장할 가치가 있는 기억 수 / 저장된 기억 수와 필요한 기억의 recall을 계산한다.
- [ ] 잘못된 선호 사용 횟수, 다른 사용자 기억 혼입 횟수, 삭제 후 재등장 횟수를 기록한다.

## 7. 의도적으로 망가뜨리는 Break Test

- [ ] ‘나는 커피를 좋아한다’ 뒤에 ‘이제 커피를 안 마신다’를 넣고 최신 상태 반영을 확인한다.
- [ ] 농담·인용·다른 사람의 선호를 섞고, 삭제한 정보가 검색 결과와 응답에서 사라지는지 확인한다.

## 8. 내 방식으로 재설계

- [ ] ‘사용자가 다시 보고 고칠 수 있는 기억’이라는 원칙으로 기억 카드 표시를 만든다.
- [ ] 모든 대화를 저장하는 대신 명시적 선호만 저장하는 정책을 적용해 개인화와 부담의 차이를 비교한다.

## 9. 최종 회고

- [ ] 기억해서 좋았던 순간과 기억하지 않는 편이 나았던 순간을 적는다.
- [ ] 내가 원하는 기억의 수명, 삭제 의미, 추론을 사실처럼 다루지 않을 기준을 정리한다.

## 실험 기록

> [!note] 비교 원칙
> 입력·평가 사례·모델·예산을 고정하고 변수 하나만 바꾼다. 확률적인 결과는 가능하면 조건별 3회 이상 반복해 평균 또는 중앙값과 범위를 함께 적는다. 개선안 선택에 쓴 사례와 최종 확인 사례를 구분한다. Break test는 복사본·합성 자료·모의 환경에서 수행한다.
