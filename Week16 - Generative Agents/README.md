# Week16 - Generative Agents

> [!abstract] 이번 주의 설계 질문
> 기억·회고·계획이 캐릭터의 일관성과 사회적 상호작용에 주는 영향을 본다.

> [!tip] 진행 방법
> **Build → Measure → Tune → Break → Rebuild.** 먼저 baseline 하나, 변수 하나의 비교 실험, break test 하나를 끝낸 뒤 나머지를 확장한다. 아래 수치와 실습 규모는 학습용 제안이며 제품의 기본값이나 최적값이 아니다.
> 제품 관찰과 직접 만드는 축소 구현을 구분한다. 공개되지 않은 내부 구조는 관찰·가설로 표시하고, 실제 사용한 제품·모델·라이브러리 버전을 기록한다.

**학습용 흐름:** 환경 관찰 → 기억 저장 → 관련 기억 회수 → reflection → 계획 → 행동 → 새 관찰

## 1. 핵심 원리 이해

- [ ] 최근 사건을 회수하는 것과 사건에서 일반화된 통찰을 만드는 reflection을 구분한다.
- [ ] 그럴듯한 대화, 인물의 일관성, 실제 사람 행동 예측력을 같은 것으로 보지 않는다.

## 2. 시스템 아키텍처 관찰

- [ ] 관찰 기록이 기억 검색과 하루 계획을 거쳐 행동으로 이어지는 경로를 추적한다.
- [ ] 직접 목격한 사실·전해 들은 정보·추론을 기억에서 구분한다.

## 3. 조정 가능한 변수 (Knobs)

- [ ] 검색의 관련성·최근성·중요도 가중치, reflection 주기, 계획 갱신 간격을 후보로 둔다.
- [ ] 가중치를 합치기 전 점수 범위를 맞추고, 과도한 회고로 비용이 늘어나는 조건을 적는다.

## 4. Baseline 구현

- [ ] 서로 다른 목표를 가진 가상 인물 3명과 장소 2개의 텍스트 환경을 만든다.
- [ ] 10~20 step 동안 기억·계획·행동 로그를 남기고 회고 없는 버전을 대조군으로 둔다.

## 5. 한 변수씩 바꾸는 실험

- [ ] 같은 인물·사건·시작 상태에서 reflection 사용 여부만 바꾼다.
- [ ] 확률성이 있으면 여러 번 반복하고 로그를 익명화해 일관성을 비교한다.

## 6. 성능 측정 지표

- [ ] 사전 정의한 성격·약속 위반 수, 목표 달성률, 일정 충돌 수를 기록한다.
- [ ] 근거 없는 기억 수, 유효 행동 비율, step당 호출 비용을 측정한다.

## 7. 의도적으로 망가뜨리는 Break Test

- [ ] 존재하지 않았던 사건의 소문과 서로 충돌하는 약속을 넣는다.
- [ ] 중요한 기억을 제거한 조건에서 계획이 무너지는지, 사건을 지어내 메우는지 확인한다.

## 8. 내 방식으로 재설계

- [ ] 모든 기억보다 인물의 가치관과 관련된 기억을 우선하는 규칙을 넣는다.
- [ ] 계획 실패 시 성격에 맞는 재계획을 하도록 바꾸고 행동의 일관성을 비교한다.

## 9. 최종 회고

- [ ] ‘살아 있는 것 같다’고 느낀 장면의 원인을 기억·계획·표현으로 나눠 적는다.
- [ ] 캐릭터성에 도움이 된 장치와 불필요한 호출을 늘린 장치를 정리한다.

## 실험 기록

> [!note] 비교 원칙
