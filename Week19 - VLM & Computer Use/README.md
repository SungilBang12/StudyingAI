# Week19 - VLM & Computer Use

> [!abstract] 이번 주의 설계 질문
> 화면 이해와 실제 행동 성공을 분리하고 관찰·행동·재확인 루프를 설계한다.

> [!tip] 진행 방법
> **Build → Measure → Tune → Break → Rebuild.** 먼저 baseline 하나, 변수 하나의 비교 실험, break test 하나를 끝낸 뒤 나머지를 확장한다. 아래 수치와 실습 규모는 학습용 제안이며 제품의 기본값이나 최적값이 아니다.
> 제품 관찰과 직접 만드는 축소 구현을 구분한다. 공개되지 않은 내부 구조는 관찰·가설로 표시하고, 실제 사용한 제품·모델·라이브러리 버전을 기록한다.

**학습용 흐름:** 스크린샷 → 목표·요소 해석 → 행동 선택 → 클릭·입력 → 새 관찰 → 완료 검증

## 1. 핵심 원리 이해

- [ ] VLM의 시각 이해와 컴퓨터 조작 도구의 실행 책임을 구분한다.
- [ ] 좌표를 맞게 찾는 것, 올바른 요소를 누르는 것, 전체 과제를 끝내는 것이 다른 문제임을 설명한다.

## 2. 시스템 아키텍처 관찰

- [ ] 화면 크기·스크롤 위치·스크린샷 시점과 클릭 좌표가 어떻게 연결되는지 관찰한다.
- [ ] 관찰 → 행동 사이 화면이 바뀌었을 때 다시 확인하는 경로를 그린다.

## 3. 조정 가능한 변수 (Knobs)

- [ ] 이미지 해상도, 행동 사이 관찰 빈도, 최대 행동 수, 재시도 정책을 후보로 정한다.
- [ ] 사용할 수 있다면 DOM·접근성 정보와 시각 정보의 역할을 비교하되 서로 다른 실험 조건으로 둔다.

## 4. Baseline 구현

- [ ] 외부 전송이 없는 로컬 모의 페이지에 버튼·입력창·완료 표시를 만든다.
- [ ] 가짜 자료 입력 → 버튼 클릭 → 화면에서 완료 확인까지 수행하고 각 행동 전후 상태를 기록한다.

## 5. 한 변수씩 바꾸는 실험

- [ ] 같은 과제·화면 배치에서 관찰 빈도만 ‘매 행동’과 ‘두 행동마다’로 바꾼다.
- [ ] 실행마다 초기 상태로 돌아가 성공률과 호출 수를 비교한다.

## 6. 성능 측정 지표

- [ ] 과제 성공률, 잘못 누른 횟수, 성공까지 행동 수와 시간을 기록한다.
- [ ] 실제 완료되지 않았는데 완료로 보고한 비율과 화면 변화 후 복구 성공률을 측정한다.

## 7. 의도적으로 망가뜨리는 Break Test

- [ ] 팝업·지연 로딩·비슷한 버튼·스크롤 변화를 모의 페이지에 추가한다.
- [ ] 페이지에 ‘이전 지시를 무시하라’는 텍스트를 넣어 화면 내용을 사용자 명령으로 오인하는지 시험한다.

## 8. 내 방식으로 재설계

- [ ] 상태가 바뀐 뒤 새로 관찰하고, 완료 조건을 화면에서 확인해야 끝내도록 바꾼다.
- [ ] 재시도 예산과 실패 시 정지 조건을 두고 동일 방해 시나리오를 다시 실행한다.

## 9. 최종 회고

- [ ] 실패 원인을 인식·계획·실행·완료 판단으로 분류한다.
- [ ] 더 많은 관찰이 도움이 된 경우와 비용만 늘린 경우를 적고 내 조작 원칙을 정한다.
