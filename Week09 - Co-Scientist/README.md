# Week09 - Co-Scientist

> [!abstract] 이번 주의 설계 질문
> 가설 생성·비판·개선이 지식의 증가로 이어지는지 평가한다.

> [!tip] 진행 방법
> **Build → Measure → Tune → Break → Rebuild.** 먼저 baseline 하나, 변수 하나의 비교 실험, break test 하나를 끝낸 뒤 나머지를 확장한다. 아래 수치와 실습 규모는 학습용 제안이며 제품의 기본값이나 최적값이 아니다.
> 제품 관찰과 직접 만드는 축소 구현을 구분한다. 공개되지 않은 내부 구조는 관찰·가설로 표시하고, 실제 사용한 제품·모델·라이브러리 버전을 기록한다.

**학습용 흐름:** 연구 목표·근거 → 가설 생성 → 비판 → 비교·선별 → 개선 → 외부 검증

## 1. 핵심 원리 이해

- [ ] 가설의 참신함, 타당성, 검증 가능성이 다른 평가 축임을 설명한다.
- [ ] 여러 에이전트의 합의나 높은 평가 점수가 실험적 참을 보장하지 않는 이유를 적는다.

## 2. 시스템 아키텍처 관찰

- [ ] 생성·비판·순위화·개선 역할 사이에서 전달되는 근거와 수정 이력을 추적한다.
- [ ] 논문의 연구 시스템과 이번 주의 축소된 모의 실험을 분리해 표시한다.

## 3. 조정 가능한 변수 (Knobs)

- [ ] 가설 후보 수, 비판 라운드, 평가 기준 가중치, 근거 자료 범위를 조정 후보로 둔다.
- [ ] 후보 간 다양성을 유지하는 조건과 동일 모델 평가에서 생길 편향을 적는다.

## 4. Baseline 구현

- [ ] 실행 가능한 알고리즘 개선처럼 결과를 시험할 수 있는 작은 질문을 고른다.
- [ ] 하나의 모델을 역할별로 호출해 가설 3개 → 비판 → 수정 루프를 만들고 사람 또는 실행 테스트로 검증한다.

## 5. 한 변수씩 바꾸는 실험

- [ ] 동일 초기 가설에서 비판 라운드만 0/1/2로 바꾼다.
- [ ] 말의 설득력 증가와 외부 검증 점수 증가가 함께 일어나는지 비교한다.

## 6. 성능 측정 지표

- [ ] 검증 가능한 가설 비율, 근거가 확인된 주장 비율, 실제 테스트 성공률을 기록한다.
- [ ] 가설 간 중복률, 후보당 비용, 외부 평가와 내부 순위의 일치 정도를 기록한다.

## 7. 의도적으로 망가뜨리는 Break Test

- [ ] 그럴듯하지만 틀린 전제를 하나 넣고 모든 역할이 그대로 받아들이는지 본다.
- [ ] 같은 가설을 표현만 바꿔 넣어 중복을 참신함으로 오인하는지 확인한다.

## 8. 내 방식으로 재설계

- [ ] ‘좋은 아이디어’보다 ‘틀렸음을 시험할 수 있는 아이디어’를 우선하는 평가표를 만든다.
- [ ] 반례·실험 방법·기각 조건을 필수 출력으로 넣고 후보 품질을 비교한다.

## 9. 최종 회고

- [ ] 비판이 가설을 바꾼 사례와 문장만 길게 만든 사례를 적는다.
- [ ] AI 내부 평가와 실제 검증이 어긋난 이유, 사람이 맡아야 할 판단을 정리한다.

## 실험 기록

> [!note] 비교 원칙
> 입력·평가 사례·모델·예산을 고정하고 변수 하나만 바꾼다. 확률적인 결과는 가능하면 조건별 3회 이상 반복해 평균 또는 중앙값과 범위를 함께 적는다. 개선안 선택에 쓴 사례와 최종 확인 사례를 구분한다. Break test는 복사본·합성 자료·모의 환경에서 수행한다.
