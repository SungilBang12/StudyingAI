# Week15 - Recommender Systems

> [!abstract] 이번 주의 설계 질문
> 취향 적합도·새로움·다양성 사이에서 내가 원하는 추천 성질을 선택한다.

> [!tip] 진행 방법
> **Build → Measure → Tune → Break → Rebuild.** 먼저 baseline 하나, 변수 하나의 비교 실험, break test 하나를 끝낸 뒤 나머지를 확장한다. 아래 수치와 실습 규모는 학습용 제안이며 제품의 기본값이나 최적값이 아니다.
> 제품 관찰과 직접 만드는 축소 구현을 구분한다. 공개되지 않은 내부 구조는 관찰·가설로 표시하고, 실제 사용한 제품·모델·라이브러리 버전을 기록한다.

**학습용 흐름:** 사용자·아이템·행동 → 후보 생성 → 점수화 → 재정렬 → 노출 → 피드백

## 1. 핵심 원리 이해

- [ ] 명시적 선호와 클릭 같은 암묵적 피드백의 차이를 설명한다.
- [ ] 클릭하지 않은 아이템이 싫은 것인지 보지 못한 것인지 구분하기 어려움을 이해한다.

## 2. 시스템 아키텍처 관찰

- [ ] 후보 생성과 최종 재정렬을 나눠 어느 단계에서 다양성이 사라지는지 본다.
- [ ] 학습 자료와 평가 자료를 시간순으로 나누고 미래 행동이 특성에 들어가지 않도록 한다.

## 3. 조정 가능한 변수 (Knobs)

- [ ] 유사도 기준, 이웃 수, 인기 가중치, 다양성 패널티, 탐색 비율을 후보로 정한다.
- [ ] 후보 수를 늘리는 것과 최종 추천 목록 길이를 늘리는 것을 구분한다.

## 4. Baseline 구현

- [ ] 작은 공개 상호작용 자료 또는 직접 평가한 아이템 목록을 준비한다.
- [ ] 인기순 추천을 대조군으로 만들고 태그·특성 유사도 기반 추천을 하나 추가한다.

## 5. 한 변수씩 바꾸는 실험

- [ ] 후보와 관련성 점수를 고정하고 다양성 패널티만 0/낮음/높음으로 바꾼다.
- [ ] 튜닝에 쓰지 않은 평가 사용자·기간에서 관련성과 다양성 변화를 함께 확인한다.

## 6. 성능 측정 지표

- [ ] 관련성 라벨로 Recall@k 또는 NDCG@k를 계산하고 어떤 라벨을 정답으로 썼는지 적는다.
- [ ] 목록 내 다양성, 카탈로그 coverage, 인기 편중과 본인이 느끼는 유용성을 별도로 기록한다.

## 7. 의도적으로 망가뜨리는 Break Test

- [ ] 신규 사용자·신규 아이템·인기 아이템에 치우친 기록을 넣는다.
- [ ] 한 번의 우연한 클릭을 여러 번 복제해 취향이 과도하게 바뀌는지 확인한다.

## 8. 내 방식으로 재설계

- [ ] ‘익숙한 것 3개+새로운 것 2개’처럼 나의 추천 철학을 규칙 하나로 표현한다.
- [ ] 관심 없음·이미 봄 피드백을 분리해 추천에 반영하고 목록 변화를 비교한다.

## 9. 최종 회고

- [ ] 수치가 높았지만 마음에 들지 않았던 목록과 그 이유를 기록한다.
- [ ] 내 취향을 좁힌 추천과 넓힌 추천의 차이, 온라인 행동 데이터 없이 말할 수 없는 결론을 적는다.

## 실험 기록

> [!note] 비교 원칙
> 입력·평가 사례·모델·예산을 고정하고 변수 하나만 바꾼다. 확률적인 결과는 가능하면 조건별 3회 이상 반복해 평균 또는 중앙값과 범위를 함께 적는다. 개선안 선택에 쓴 사례와 최종 확인 사례를 구분한다. Break test는 복사본·합성 자료·모의 환경에서 수행한다.
